Projects turn familiarity into skill. Choose a scope you can finish and publish.

## Choosing a project

Prefer a project that is:

- **Finishable in one to three weeks** at your current level
- **Useful to one real person** — even if that person is you
- **Demonstrable** — someone else can use it from a link
- **Explainable** — you can describe the decisions and trade-offs

## A healthy project brief

Write down the user, the problem, the core workflow, what is out of scope, and how you will know it works. Keep the first version smaller than you think it needs to be.

## Project ideas by level

### Starting out

- A personal introduction page with responsive layout
- A command-line expense tracker
- A study-log page that saves notes in the browser

### Building confidence

- A weather dashboard using a public API
- A bookmark manager with search and tags
- A test-covered REST API for a small personal dataset

### Going further

- A retrieval-augmented question-answering tool over your own notes
- A task assistant that uses tools with confirmation before side effects
